# D4.2 — owner-scoped library and migration6

Status: passed for local prototype implementation; hosted storage remains unavailable.
Dependencies: A3561e93d1bae4ec78fd661e0729fbf53322252c4, D9605f496c226b2275ebc767b87ec9a9899f1d0e2.

All5 agreed document operations are implemented/advertised by documents.OPERATIONS.
Authentication remains Application's bearer owner; every SQL target uses owner+ID,
including drafts/retry keys. No body owner/path is accepted. JSON/base64 transport
uses A's existing route-specific bound, no multipart/new server framework.

Migration6 extends the same SQLite DB: library_documents (metadata/lifecycle),
library_requests (owner/key/operation/request hash/target only), library_drafts
(links into existing drafts). Existing profile/plan/task/history tables untouched.
Fresh/repeat and disposable v5 upgrade are tested. No source bytes/base64/text enter
library metadata/receipts/logs; text exists only in an explicitly requested private
intake draft. Client metadata strips internal object keys and never returns paths.

Upload validates bounded types/extensions/signatures/UTF-8/base64 before reserving
quota. Reservations commit as uploading before object I/O; exact retries resume
that same ID. Active status is committed only after bytes succeed. Failed/stuck
uploading rows remain visible, count toward limits and can be retried/deleted.
No background jobs or provider calls. Duplicate upload requests cannot duplicate files;
changed retry scope fails409, deleted upload receipts cannot resurrect files.

Storage is disabled by default; list returns explicit storage.status unavailable,
mode disabled. Set MINDER_DOCUMENT_STORAGE=local-development for private local files
under the current DB parent's uploads/documents. Optional MINDER_DOCUMENT_STORAGE_ROOT
must remain an absolute path inside that same lane uploads subtree, never a public
web root. Local is explicitly durable_hosting_verified:false. Unknown backends fail
closed, with document_storage_backend_not_configured; no hosted local-file fallback.
File/count/byte environment names/defaults follow D4 contract; max per file1MiB.

List also returns usage.file_count/stored_or_reserved_bytes and extraction capability
{supported_types:['text/plain'],max_text_bytes:65536,pdf_status:'unavailable',
automatic_profile_apply:false}. Each metadata document contains current version;
extract may change it, so use the returned version/refetch before deletion.

Download checks owner/lifecycle before storage, verifies size/hash, and returns
{document,content_base64,download_content_type:'application/octet-stream'}. F should
use a download attachment, never inline PDF/HTML and never token-in-URL links.
TXT extract reuses profiles._intake_draft (same validation/record as /api/intake),
with one surviving draft per source. Repeated extract returns it, including reviewed
status after apply. Existing /intake-correction applies only explicit reviewed fields.
PDF/oversized TXT extraction returns reasoned unavailable + draft:null; manual
profile entry works even with storage disabled or extraction unavailable.

Delete checks current expected_version and records exact retry scope. It first
quarantines as deleting and purges linked pending/reviewed draft rows; download,
extract and new profile apply via that draft can no longer proceed. It then removes
object bytes and scrubs metadata to {document_id,status:'deleted',deleted_at}.
Success returns only after byte deletion; retries are idempotent. A storage deletion
failure leaves deleting, retains quota/storage key for retry, returns500 and never
pretends removal. List includes this state so F can retry the same request. Reuse
its original idempotency key/body; new delete intent during deletion fails409.

Already reviewed/applied profile fields, their history and authority/product retry
records remain. Original byte hashes in hashed request receipts/tombstone IDs remain
for non-resurrection/idempotency; no original file/name/text survives in the library
metadata after completed delete. SQLite freed pages/WAL and external backups are
not securely erased; no account-erasure/retention/encryption guarantee is claimed.
No automatic file/draft expiry or asynchronous extraction/provider use is introduced.
A process interruption can leave an uploading reservation or deleting intent;
retry or explicit deletion resolves it. Local storage is not a verified durable host.
